# MyBicocca Data API

The Kotlin SDK of the University of Milano-Bicocca's services, which the Android app builds on.
Every source in `src/main` is generated by [`common/codegen`](../../common/codegen) from the specs
in [`common/specs`](../../common/specs), which also produce the Swift and web SDKs; files starting
with `Generated by MyBicocca codegen` must not be edited. Change a spec and run the generator
instead.

The SDK neither logs in nor chains requests: the university's SSO logins, and flows such as
booking an appointment or marking a presence, live in the app.

## APIs

| Facade                 | Spec                                | Service                                                                  |
|------------------------|-------------------------------------|--------------------------------------------------------------------------|
| `Esse3Api`             | `common/specs/esse3`                | [Esse3](https://s3w.si.unimib.it): careers, exams, fees, self-declarations ([docs](docs/esse3.md)) |
| `MoodleApi`            | `common/specs/moodle`               | [Moodle](https://elearning.unimib.it)'s web services and file endpoints ([docs](docs/elearning.md)) |
| `MoodleWebApi`         | `common/specs/moodle-web`           | Moodle's pages: course catalog, video players, attendance                 |
| `KalturaApi`           | `common/specs/kaltura`              | Kaltura's CDN, which serves the lecture recordings                        |
| `EasyStaffApi`         | `common/specs/easystaff-agenda`     | Agenda Web and EasyBadge: timetables, exams, rooms, attendance ([docs](docs/easystaff.md)) |
| `EasyStaffPlanningApi` | `common/specs/easystaff-planning`   | Portale Planning: appointments at the student information desks         |
| `AffluencesApi`        | `common/specs/affluences`           | Affluences: library study room reservations                              |

Each lives in its own package under `it.attendance100.mybicocca.data.remote`, with its modules in
`api`, its records in `dto` and its exception in `exception`. The runtime they share (requests,
error handling and retries, file uploads) is in `data.remote.runtime`, generated too.

## Usage

```kotlin
val esse3 = Esse3Api { install(Auth) { basic { … } } }
val careers = esse3.careers.getCareers(userId = "…")

val moodle = MoodleApi().apply { language = "it" }
val courses = moodle.course.getUsersCourses(userId, auth = MoodleTokenAuth(token))

val agenda = EasyStaffApi()
val buildings = agenda.buildings.getBuildings()
```

Facades are `AutoCloseable` and own their HTTP client; the trailing block configures it. A request
the service rejects throws the API's exception (`Esse3Exception`, `MoodleException`, …), a
`runtime.ApiException` with the status, the service's error code and its message; each exception
names the codes callers may want to handle, such as `MoodleException.INVALID_TOKEN`.

## Tests

`src/test` holds the live tests, generated like the SDK from each API's `tests.yaml`. They call
the real services, and the iOS and web SDKs run the same cases (see "Live tests" in the
[codegen README](../../common/codegen)). `test` leaves them out; `liveTest` runs them, skipping
the APIs whose account isn't in the environment:

```sh
./gradlew -p data-api liveTest                                         # every API
ESSE3_USERNAME=… ESSE3_PASSWORD=… ./gradlew -p data-api liveTest --tests "*.esse3.live.*"
```

Reports go to `build/live-reports`.

Requires JDK 17+.
