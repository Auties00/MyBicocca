# E-Learning API Module

Kotlin clients for the university's Moodle, [elearning.unimib.it](https://elearning.unimib.it/).
`ElearningApi` groups them, sharing one HTTP client and the user's Moodle session:

| Property     | What it is                                                                                     |
|--------------|------------------------------------------------------------------------------------------------|
| `moodle`     | The Moodle web service functions, generated from `common/specs/moodle` (`MoodleApi`)            |
| `catalog`    | The public course pages, scraped, generated from `common/specs/moodle-web`                     |
| `attendance` | The attendance plugin: summaries from `view.php`, self-marking through its mobile templates    |
| `kaltura`    | Playback of Kaltura video resources                                                             |
| `files`      | File download and upload                                                                        |

Files starting with `Generated by MyBicocca codegen` are generated by `common/codegen` and must
not be edited. `attendance`, `kaltura` and `files` are hand-written: they chain requests, as
marking does, or call services other than Moodle, as Kaltura playback does.

This module does not log in: the university SSO login (a SAML/Shibboleth flow that ends on a
`moodlemobile://token=BASE64_DATA` redirect) lives in the app, which passes the resulting token to
each call and the `MoodleSession` cookie to the constructor. The cookie is only needed by the
web pages that show the user's own data, such as attendance and video resources.

## Web service functions

Most data comes from Moodle's REST web services, called with the user's token:

```kotlin
val api = ElearningApi(moodleSessionCookie = moodleSession)
val auth = MoodleTokenAuth(token)
val userId = api.moodle.site.getSiteInfo(auth = auth).userId
val courses = api.moodle.course.getUsersCourses(userId, auth = auth)
```

## Pages

What no web service exposes is read out of Moodle's pages (see `common/specs/moodle-web`):

- `catalog`: a course's public page (syllabus, staff, enrolment methods), for any course. It is
  fetched without the session, as Moodle renders it to anonymous visitors. The course sheet
  ("Scheda del corso") comes from the course's custom fields instead
  (`moodle.course.getCoursesByField`).
- the Kaltura player of a video resource, which needs the session; `kaltura` uses it to find
  the video's Kaltura entry;
- the attendance plugin's `view.php` and mobile templates, which `attendance` reads with the
  generated `MoodleWebScrapers`. The plugin's mobile view of an activity is never rendered for
  reading: doing so marks the student present in open sessions that assign a status by
  themselves.

## Tests

The tests call the live site and are tagged `live`. `MoodleWebApiTest` needs nothing; the web
service tests need a token in `MOODLE_TOKEN`:

```sh
MOODLE_TOKEN=... ./gradlew -p data-api :elearning:test -PincludeLive --tests "*.MoodleApiTest" --tests "*.MoodleWebApiTest"
```
