# MyBicocca for iOS

The iOS app will live here. For now this folder holds [`DataApi`](DataApi), the Swift package
the app will use to talk to the university's services.

## DataApi

Everything in `DataApi/Sources` is generated by [`common/codegen`](../common/codegen) from the
specs in [`common/specs`](../common/specs), and so are the live tests in `DataApi/Tests/LiveTests`.
Only `Package.swift` and the runtime's tests are written by hand. To change an API, edit its spec
and regenerate; don't edit the Swift files.

The package mirrors the Android SDK: one module per service, each split the same way.

| Module           | Android package   | What's in it                                   |
|------------------|-------------------|------------------------------------------------|
| `Esse3`          | `esse3`           | Esse3: careers, exams, fees, self-declarations |
| `Elearning`      | `elearning`       | Moodle, Moodle's pages and Kaltura             |
| `EasyStaff`      | `easystaff`       | Agenda Web, EasyBadge and Portale Planning     |
| `Affluences`     | `affluences`      | Affluences: library study rooms                |
| `DataApiRuntime` | `runtime`         | What the generated code builds on              |

Inside each module:

| Folder    | Android folder | Contents                                         |
|-----------|----------------|--------------------------------------------------|
| `API`     | `api`          | The entry point, one service per module, the client |
| `Models`  | `dto`          | Records, enums, credentials and scrapers         |
| `Errors`  | `exception`    | The error each API throws                        |

Add the `DataApi` product to the app and import the modules it needs:

```swift
import Esse3

let esse3 = Esse3Api(configuration: RestConfiguration(
    baseURL: Esse3Client.defaultConfiguration.baseURL,
    headers: ["Authorization": "Basic …"]
))
let careers = try await esse3.careers.getCareers(userId: "…")
```

A request the service rejects throws the API's error, such as `Esse3Error`, with the status and
the service's error code.

Run the tests with `swift test` from `DataApi` (macOS only). The live tests call the real
services, so they are skipped unless `LIVE_TESTS=1`:

```sh
LIVE_TESTS=1 MOODLE_TOKEN=… swift test --filter LiveTests.Moodle
```

See "Live tests" in the [codegen README](../common/codegen) for what they check.
